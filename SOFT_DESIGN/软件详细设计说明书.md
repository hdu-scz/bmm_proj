## 1. 引言

### 1.1 编写目的

本文档为 BMS 从控模块的软件详细设计说明书，依据《BMS 从控模块 软件需求规格说明书》（BMS-SLAVE-SRS-001）展开。本文档采用分层对象化设计方法，定义每个设计单元的唯一标识并建立与需求的双向追溯关系，为编码实现提供精确指导。

### 1.2 适用范围

适用于基于 GD32F30x + 4× GT2818S 的 BMS 从控模块嵌入式软件编码与测试。已编码对象以 `CODE/` 为准；BSW 及之后章节是目标设计，仓库中尚无对应源文件。

### 1.3 术语与缩写

参见 SRS 文档 §1.3。

### 2.2 层级定义与职责

| 层级 | 全称 | 职责 | 说明 |
|------|------|------|------|
| **STRATEGY** | Strategy Layer | 封装不同项目的差异化策略 | 未设计，无代码 |
| **BSW** | Basic Software | 实现 SRS 功能需求，编排 BSP 对象完成业务逻辑 | 目标设计，无代码 |
| **BSP** | Board Support Package | 封装板级芯片的驱动逻辑 | 已编码对象直接持有 MCAL 指针 |
| **MCAL** | Microcontroller Abstraction Layer | 对象化封装 MCU 外设，调用下层 HAL API | 已编码，见 §6 |
| **HAL** | Hardware Abstraction Layer | 厂商提供的 MCU 标准外设库 | 本层为 GD32 官方库，直接操作寄存器 |
| **CPU** | Chip Foundation | MCU 芯片启动依赖的基础文件 | 启动文件、链接脚本、系统时钟配置等 |

### 2.4 设计原则

1. **单向依赖**：上层依赖下层，下层不依赖上层（STRATEGY → BSW → BSP → MCAL → HAL → CPU）
2. **接口隔离**：层间通过明确定义的接口通信，STRATEGY 层仅通过策略接口调用 BSW
3. **对象化封装**：每个设计单元以"对象"形态存在，包含属性和方法
4. **层间连接**：已编码的 BSP 直接保存 `Periph_Spi_t *`、`Periph_Gpio_t *` 或 `Periph_Can_t *`。§9 的钩子注册表是早期目标，当前代码未采用
5. **唯一标识**：每个设计单元有全局唯一标识符，与 SRS 需求建立追溯
6. **策略层**：SRS 要求用策略层隔离项目差异。该层未设计，本节不展开

## 3. 唯一标识与需求追溯体系

### 3.1 标识编码规则

```
格式: [层级]_[模块]_[序号]

层级前缀:
  CPU_xxx   — CPU 层对象
  HAL_xxx   — HAL 层对象
  MCAL_xxx  — MCAL 层对象
  BSP_xxx   — BSP 层对象
  BSW_xxx   — BSW 层对象

模块缩写:
  STARTUP, SYS, LNK, INT  — CPU
  SPI, I2C, CAN, UART, GPIO, RCU, MISC, WDT  — HAL
  SPI, I2C, CAN, UART, GPIO, TIM, WDT, NVIC  — MCAL
  AFE, EEP, MUX, CPHY, ADDR                  — BSP
  ASMP, BAL, FLT, CANC, STST, ADRS           — BSW

示例:
  MCAL_SPI_001    — MCAL 层 SPI 模块的第一个设计单元
  BSP_AFE_001     — BSP 层 AFE 模块的第一个设计单元
```

## 4. CPU 层设计

### 4.1 概述

CPU 层是整个软件的最底层，包含 MCU 芯片启动和运行所必需的**基础文件**。这些文件一般不包含业务逻辑，但它们是芯片能够正常启动、配置时钟和响应中断的前提。

CPU 层文件由芯片厂商提供或按芯片型号从模板生成，开发者通常**不需要修改**（除链接脚本和系统时钟配置外）。

### 4.2 文件清单

| 设计标识 | 文件名 | 功能 | 是否需要修改 |
|---------|-------|------|------------|
| CPU_CMSIS_001 | core_cm4.h / core_cm4_simd.h | Cortex-M4 内核头文件（标准 CMSIS） | 否 |
| CPU_CMSIS_002 | gd32f30x.h | GD32F30x 外设寄存器定义 | 否 |
| CPU_CMSIS_003 | system_gd32f30x.c/h | 系统时钟初始化与 SystemCoreClock 定义 | 是（根据晶振频率配置） |
| CPU_CMSIS_004 | startup_gd32f30x_*.s | 启动文件（cl/hd/xd 版本） | 否（直接使用厂商模板） |
| CPU_LNK_001 | gd32f30x.icf | IAR 链接脚本：定义 Flash/RAM 地址映射、堆栈大小 | 是（根据实际 Flash/RAM 配置） |

### 4.3 各文件详细说明

#### 4.3.1 CMSIS 内核文件

> **设计标识：** CPU_CMSIS_001 / CPU_CMSIS_002

**功能：**
- `core_cm4.h`、`core_cm4_simd.h`、`core_cmFunc.h`、`core_cmInstr.h`：ARM Cortex-M4 内核标准 CMSIS 头文件，提供内核寄存器访问、指令仿真、中断控制等接口。
- `gd32f30x.h`：GD32F30x 系列外设寄存器定义及位带操作宏。

#### 4.3.2 系统时钟文件 `system_gd32f30x.c/h`

> **设计标识：** CPU_CMSIS_003

**功能：** 在启动阶段配置系统时钟并定义 `SystemCoreClock` 全局变量。

**当前代码选择的时钟（`system_gd32f30x.c`）：**

```
#define __SYSTEM_CLOCK_48M_PLL_HXTAL  (48000000)
```

核心时钟为 48 MHz HXTAL PLL。下面曾按 72 MHz 描述的时钟树是旧草案，不能当作当前配置。CAN 初始化注释仍按 72 MHz / (1+6+3) / 9 = 500 kbps 计算，与 48 MHz 不一致，见附录 D。

#### 4.3.3 启动文件 `startup_gd32f30x_*.s`

> **设计标识：** CPU_CMSIS_004

**功能：**
- 定义堆栈指针（SP）初始值
- 定义中断向量表（从 Reset_Handler 开始）
- 调用 `SystemInit()` 初始化系统时钟
- 初始化 .data 段（从 Flash 复制到 RAM）
- 清零 .bss 段
- 跳转到 `main()` 函数

**向量表示意：**
```
中断向量表 (存放在 Flash 起始地址 0x08000000):
  0x00000000: 堆栈顶地址 (由 ICF 文件定义)
  0x00000004: Reset_Handler
  0x00000008: NMI_Handler
  0x0000000C: HardFault_Handler
  0x00000010: MemManage_Handler
  ... (其他异常和中断向量)
```

#### 4.3.4 链接脚本 `gd32f30x.icf`

> **设计标识：** CPU_LNK_001

**功能：** 定义芯片的内存地址映射和段布局。

**关键定义：**
```
FLASH 起始地址: 0x08000000
RAM 起始地址:   0x20000000

段布局:
  .intvec  → Flash 起始 (中断向量表)
  .text    → Flash (代码段)
  .rodata  → Flash (只读数据)
  .data    → RAM (初始化数据，从 Flash 复制)
  .bss     → RAM (零初始化数据)
  .stack   → RAM 末尾 (堆栈)
  .heap    → RAM (堆，可选)
```

## 5. HAL 层设计

### 5.1 概述

HAL 层（Hardware Abstraction Layer）是芯片厂商（GD32）提供的**标准外设库**。它封装了对 MCU 寄存器的直接操作，为上层提供 API 级别的接口。

HAL 层的文件**直接从厂商 SDK 中获取**，开发者通常不需要（也不应该）修改这些文件。MCAL 层的对象方法内部调用 HAL 层的 API 完成实际的寄存器读写。

> **重要原则：** MCAL 层调用 HAL API，HAL 层不依赖任何上层。如果需要移植到其他 MCU 平台，只需替换 HAL 层（以及对应的 CPU 层）即可，MCAL 层及以上代码无需改动。

## 6. MCAL 层设计

### 6.1 概述

MCAL 层是对 GD32F30x MCU 内部硬件外设的**对象化封装层**。每个外设（SPI、I2C、CAN 等）被抽象为一个**对象**，包含：

- **成员变量**（Attributes）：描述外设的状态和配置
- **成员方法**（Methods）：通过函数指针实现的操作接口

MCAL 对象调用 HAL API，不直接写寄存器。已编码的 BSP 保存 MCAL 对象指针，不使用下文 §9 的钩子表。

### 6.2 对象清单

已编码：

| 设计标识 | 代码对象 | 硬件 |
|---------|---------|------|
| MCAL_SPI_001 | `periph_spi0` | SPI0，PA5/PA6/PA7，8 bit，MSB，`SPI_PSC_8`，`SPI_CK_PL_HIGH_PH_2EDGE`，软件 NSS。方法：`init`、`deinit`、`send_array`、`read_array`。片选不在本对象内 |
| MCAL_CAN_001 | `periph_can0` | CAN0，PB8 RX，PB9 TX，目标 500 kbps，FIFO0 全通滤波，接收中断。方法含 `transmit`、`receive`、`register_rx_callback` |
| MCAL_I2C_001 | `periph_softi2c0` | PB6 SCL，PB7 SDA，默认标准速率。方法：`init`、`write`、`read`、`set_speed_mode` |
| MCAL_DWT_001 | `periph_dwt` | DWT 微秒延时 |
| MCAL_GPIO_001 | `periph_io[18]` | 见附录 C。方法：`init`、`write`、`read`、`toggle` |
| MCAL_UART_001 | `periph_uart0/1/2/3` | 115200。引脚见附录 C |
| MCAL_ADC_001 | `periph_adc1`、`periph_adc2` | 共用 ADC0。PC0 通道 10，PC2 通道 12。用途待定 |

尚未编码，不要当成已有对象：看门狗 `Wdt`、`NvicMgr`、SysTick `TimerSys`。

### 6.3 SPI 外设对象

> **设计标识：** MCAL_SPI_001  
> **代码对象：** `periph_spi0`  
> **引脚：** PA5 = SCK，PA6 = MISO，PA7 = MOSI

6.3 之后若仍出现 SPI1、PB13～PB15 或片选方法，那些是旧草案。片选由 `periph_io` 完成。`periph_spi.c` 的 `init` 访问了结构体中不存在的 `self->pins`，字段名是 `physical_pins`，见附录 D。

#### 6.3.1 对象属性

```
对象 SpiDevice_t (spi1):
  属性:
    - spi_periph            : SPI 外设基地址 (SPI0/SPI1/SPI2)
    - baudrate_prescaler    : 波特率分频系数
    - clock_polarity        : 时钟极性 (CPOL)
    - clock_phase           : 时钟相位 (CPHA)
    - frame_size            : 数据帧长度 (8bit/16bit)
    - direction             : 通信方向
    - state                 : 当前状态
    - error_code            : 错误码
```

#### 6.3.2 对象方法

```
方法 spi1.init():
  功能: 初始化 SPI1 外设、配置引脚复用、设置时钟极性/相位、
        配置波特率分频器、使能 SPI 外设
  输出: 无

方法 spi1.deinit():
  功能: 禁用 SPI 外设、释放时钟
  输出: 无

方法 spi1.chip_select_low(port, pin):
  功能: 拉低指定 GPIO 端口和引脚（选中从机）
  输入: port — GPIO 端口, pin — 引脚号

方法 spi1.chip_select_high(port, pin):
  功能: 拉高指定 GPIO 端口和引脚（释放从机）
  输入: port — GPIO 端口, pin — 引脚号

方法 spi1.send_array(data, size, timeout):
  功能: 通过 SPI 发送指定长度的数据数组
  输入: data — 发送缓冲区指针, size — 数据长度, timeout — 超时时间
  输出: 成功/失败状态

方法 spi1.read_array(data, size, timeout):
  功能: 通过 SPI 接收指定长度的数据数组（发送 DUMMY 字节）
  输入: data — 接收缓冲区指针, size — 数据长度, timeout — 超时时间
  输出: 成功/失败状态
```

#### 6.3.3 功能设计说明

**spi_init(self)**
- 根据 `self->spi_periph` 判断外设编号，分别使能对应 SPI 时钟（RCU_SPI0/1/2）和 GPIO 时钟（RCU_GPIOA/B/C）
- 根据外设编号配置对应的 SCK/MOSI/MISO 引脚为复用推挽输出（MOSI/SCK）或浮空输入（MISO）
- 使用 `spi_parameter_struct` 配置 SPI 为主模式、全双工、8bit、NSS 软件控制、MSB 先行
- 调用 `spi_init()` 和 `spi_enable()` 完成外设初始化

**spi_deinit(self)**
- 禁用 SPI 外设
- 根据外设编号关闭对应 SPI 时钟

**spi_chip_select_high(self, port, pin)**
- 调用 `gpio_bit_set(port, pin)` 拉高片选引脚

**spi_chip_select_low(self, port, pin)**
- 调用 `gpio_bit_reset(port, pin)` 拉低片选引脚

**spi_send_array(self, data, size, timeout)**
- 循环发送 `size` 个字节
- 每次发送前等待 `SPI_FLAG_TBE` 置位
- 发送完成后等待 `SPI_FLAG_RBNE` 置位并读取接收数据（丢弃）

**spi_read_array(self, data, size, timeout)**
- 循环接收 `size` 个字节
- 每次接收前发送 dummy 字节（0xFF）
- 等待 `SPI_FLAG_RBNE` 置位后读取数据存入缓冲区

### 6.4 I2C 软件模拟对象

> **设计标识：** MCAL_I2C_001  
> **对应硬件：** 任意 2 个 GPIO 引脚 (软件模拟 I2C 时序)  
> **追溯需求：** REQ-REL-004（EEPROM 配置存储）  
> **调用 HAL：** gd32f30x_gpio（通过 GPIO 位操作实现时序）

#### 6.4.1 设计说明

本模块使用软件 GPIO 位操作模拟 I2C 总线时序，而非使用 MCU 硬件 I2C 外设。优势在于：
- 引脚选择灵活（任意 GPIO 均可）
- 时序可控，便于调试
- 跨平台移植时无需依赖硬件 I2C

#### 6.4.2 对象属性与方法

```
对象 Periph_SoftI2c_t (softi2c0):
  属性:
    - scl_port / scl_pin   : SCL 端口和引脚
    - sda_port / sda_pin   : SDA 端口和引脚
    - delay_us             : 半周期延时时间 (us)
    - speed_mode           : 速率模式 (LOW / REGULAR / FAST)

  方法:
    SoftI2c.init()
        功能: 根据 speed_mode 初始化 GPIO 为开漏输出，配置延时时间

    SoftI2c.deinit()
        功能: 释放 GPIO 引脚资源

    SoftI2c.set_speed_mode(mode)
        功能: 运行时切换 I2C 速率模式，并更新延时时间
        输入: mode — I2C_SPEED_LOW / REGULAR / FAST

    SoftI2c.write(devAddr, data, len)
        功能: 主机写数据到从设备
        流程: START → 发送设备地址+W → 发送数据字节 → STOP
        输入: devAddr — 7-bit 设备地址, data — 数据缓冲区, len — 长度
        输出: 成功/失败

    SoftI2c.read(devAddr, data, len)
        功能: 主机从从设备读取数据
        流程: START → 发送设备地址+R → 接收数据字节 → STOP
        输入: devAddr, data, len
        输出: 成功/失败

  私有方法 (内部):
    SoftI2c.start() / SoftI2c.stop()
        功能: 发送 I2C START / STOP 条件

    SoftI2c.write_byte(data) / SoftI2c.read_byte(ack)
        功能: 发送/接收一个字节，含 ACK 处理

    SoftI2c.scl_high() / SoftI2c.scl_low() 等辅助函数
        功能: GPIO 位操作 + 延时

    I2cSw.sdaHigh() / I2cSw.sdaLow()
        功能: 控制 SDA 线高低电平

    I2cSw.sdaRead()
        功能: 读取 SDA 线电平
        输出: HIGH/LOW

    I2cSw.delayHalfPeriod()
        功能: 半周期延时 (由 speedMode 决定)
```

#### 6.4.3 时序模拟说明

```
I2C START 条件:
  SCL ───────┬───
              │
  SDA ────┐  │
           └──┴───

I2C STOP 条件:
  SCL       ┌───
  ──────────┘
  SDA       ┌───
  ──────┘

数据位传输 (每 1 byte = 8 bits + 1 ACK):
  SCL 低: 发送器设置 SDA 电平
  SCL 高: 接收器采样 SDA 电平
  速率: 标准 100kHz (半周期 5μs) / 快速 400kHz (半周期 1.25μs)
```

### 7.3 AFE 设备对象

> **设计标识：** BSP_AFE_001  
> **代码类型：** `Dev_Gt2818s_t`  
> **实例：** `dev_gt2818s_01` 片选 PB12，`_02` 片选 PC4，`_03` 片选 PB1，`_04` 片选 PA2  
> **关联：** `periph.spi = &periph_spi0`，`periph.io_cs` 指向对应 GPIO

#### 7.3.1 寄存器与命令

结构见 `Afe_Register_List_t`：配置 A/B 的设定值与回读值、状态 A/B、`cell_vol_reg[6]`、`cell_aux_reg[4]`。每组电压或辅助寄存器含 3 个 `uint16_t` 加 PEC。电压 6 组共 18 路。配置 A 含 GPIO1～5 下拉、VUV/VOV、DCC1～12、DCT。配置 B 含 GPIO6～9 下拉、DCC13～18、DCC0、DTMEN。PEC15，多项式 0x4599。

| 命令 | 码 | 方法 |
|------|----|------|
| WRCFGA | 0x0001 | `write_cfg` |
| RDCFGA | 0x0002 | `read_cfg` |
| RDCVA | 0x0004 | `rdcv` |
| RDCVB | 0x0006 | `rdcv` |
| RDCVC | 0x0008 | `rdcv` |
| RDCVE | 0x0009 | `rdcv` |
| RDCVD | 0x000A | `rdcv` |
| RDCVF | 0x000B | `rdcv` |
| WRCFGB | 0x0024 | `write_cfg` |
| RDCFGB | 0x0026 | `read_cfg` |

帧格式：命令 2 字节 + PEC 2 字节。写配置再附 6 字节数据 + PEC 2 字节。唤醒为 CS 低脉冲两次，间隔约 150 μs（`periph_dwt.delay_us`）。`adcv`、`adgp` 的命令字在函数内按模式和通道拼装；`adcv` 使用了未初始化变量，见附录 D。`clrcell`、`clraux` 已实现。

#### 7.3.4 早期方法草案

> **设计标识：** BSP_AFE_002  
> **追溯需求：** REQ-DIAG-001

```
方法 Afe[id].init():
  功能: 完成 GT2818S 的上电初始化流程
  流程:
    1. hookCsSet(csPin, HIGH)               // CS 无效
    2. 通过 SPI 发送 WAKEUP 序列 (≥200mV, ≥240ns)
    3. 等待 tWAKE (≥5ms)
    4. 发送 SOFTRST 命令 (0x0052)
    5. 等待 200μs
    6. 构建 CFGA 值 → 写入 regCfgA:
       - GPIO0~7 = 模拟输入模式
       - VREF = 内部基准
       - OV_EN = 1, UV_EN = 1
       - ADC_CAL_EN = 1
    7. 调用 wrCfgA(regCfgA)
    8. 构建 CFGB 值 → 写入 regCfgB:
       - DCC[15:0] = 0x0000 (全部关闭)
       - OESEL = ODD
       - DCTO = 3600
       - BL_DUTY_SEL = 0
    9. 调用 wrCfgB(regCfgB)
    10. 构建 CFGC 值 → 写入 regCfgC (监测模式阈值)
    11. 调用 wrCfgC(regCfgC)
    12. 构建 CFGD 值 → 写入 regCfgD (测量通道选择)
    13. 调用 wrCfgD(regCfgD)
    14. 执行 selfTest() 验证初始化
  输出: 成功/失败
```

> **设计标识：** BSP_AFE_003  
> **追溯需求：** REQ-VOLT-001

```
方法 Afe[id].adcv():
  功能: 启动电压转换 (发送 ADCV 命令)
  流程:
    1. hookCsSet(csPin, LOW)
    2. 发送 16-bit 命令: [CMD=0x0010 | W/R=0 | DATA=0x00]
    3. 接收 PEC 应答
    4. hookCsSet(csPin, HIGH)
    5. 等待 tCONV (ADC 转换完成, max 100ms)
    6. PEC 校验 → 失败则 commErrCount++
  输出: 成功/失败

方法 Afe[id].rdcv():
  功能: 读取电压结果 (读取 SVD 寄存器组, 共 5 帧)
  流程:
    1. FOR i = 0 TO 4
         a. hookCsSet(csPin, LOW)
         b. 发送 RDCV 命令 (0x0012) 读取 SVD[i]
         c. 接收: [PEC(8bit) | CellA_H(8bit)] → 然后 Dummy 帧
         d. 接收: [PEC(8bit) | CellA_L + CellB_H] → 然后 Dummy 帧
         e. 接收: [PEC(8bit) | CellB_L + CellC_H] → 然后 Dummy 帧
         f. 接收: [PEC(8bit) | CellC_L + CellD 预留]
         g. hookCsSet(csPin, HIGH)
         h. PEC 校验每帧 → 存入 cellVoltageRaw[i]
         i. 解析出 3 路电压 → 存入 cellVoltage[i*3 + 0..2]
       END FOR
    2. 第 16 路 (独立读取): 类似流程
    3. 将 raw 值转换为 mV:
       cellVoltage[n] = cellVoltageRaw[n] × VREF / 65535
       VREF 典型值 = 3300mV (由 CFGA 配置)
  输出: cellVoltage[16], PEC 校验状态

方法 Afe[id].rdStat():
  功能: 读取 STAT 寄存器
  流程:
    1. 调用 readReg(0x09) 读取 STAT
    2. 解析:
       bit[0]    = alertFlag (告警)
       bit[1]    = busyFlag  (忙)
       bit[3:2]  = 自检结果
       bit[15:8] = 故障位
    3. 更新 regStat, faultStatus, alertFlag
  输出: regStat (16-bit)

方法 Afe[id].adcg(gpioIdx):
  功能: 启动 GPIO ADC 转换
  输入: gpioIdx — GPIO 通道索引 (0~7)
  流程:
    1. hookCsSet(csPin, LOW)
    2. 发送 ADCG 命令 (0x0014) + gpioIdx 参数
    3. PEC 应答
    4. hookCsSet(csPin, HIGH)
    5. 等待转换完成
  输出: 成功/失败

方法 Afe[id].rdcg(gpioIdx):
  功能: 读取 GPIO ADC 结果
  输入: gpioIdx — GPIO 通道索引 (0~7)
  流程:
    1. 调用 readReg(0x0D) 读取 GPIOD
    2. 存入 gpioAdcRaw[gpioIdx]
  输出: gpioAdcRaw[gpioIdx] (16-bit)
```

## 8. BSW 层设计

本章及 §10～§13 是目标设计，仓库中没有对应源文件。策略层未设计，不在本章补写。

名称对照：

- `Afe[0]`～`Afe[3]` 即 `dev_gt2818s_01`～`_04`
- 已实现方法是 `func.adcv`、`rdcv`、`adgp`、`rdgp`、`write_cfg`、`read_cfg`、`wakeup`、`clrcell`、`clraux`
- 伪代码里的 `setBalance`、`readGpioAdc`、`selfTest`、`hookSpiXfer` 尚未编码

### 8.4 均衡服务

> **设计标识：** BSW_BAL_001  
> **追溯需求：** REQ-BAL-001, REQ-BAL-002  
> **依赖 BSP 对象：** Afe[0..3]

#### 6.4.1 对象属性

```
对象 BalanceService:
  属性:
    - mode              : 均衡模式 (IDLE/AUTO/MANUAL)
    - balanceMask[4]    : 每颗 AFE 的均衡掩码。通道为 DCC0～DCC18，不是 16 bit
    - balStartTime      : 均衡开始时刻 (s)
    - balTimeout        : 均衡超时时间 (默认 3600s)
    - isActive          : 均衡是否进行中
    - startThreshold    : 开启阈值 (默认 20mV)
    - stopThreshold     : 停止阈值 (默认 5mV)
    - tempStopThreshold : 温度停止阈值 (默认 85℃)
```

#### 6.4.2 对象方法

```
方法 BalanceService.init():
  功能: 初始化均衡服务
        1. 关闭所有 AFE 均衡
        2. 设置默认阈值
  输出: 无

方法 BalanceService.process():
  功能: 均衡策略执行 (100ms 周期调用)
  流程:
    1. 若 mode = IDLE → 返回
    2. 检查超时: 若当前时间 - balStartTime > balTimeout → 停止均衡
    3. 检查温度: 若 maxTemp > tempStopThreshold → 停止均衡
    4. 计算压差 delta = maxCellVoltage - minCellVoltage
    5. 若 delta < stopThreshold 且 isActive → 停止均衡
    6. 若 delta ≥ startThreshold 且 !isActive → 启动均衡:
       a. 计算每颗 AFE 需均衡的电芯
       b. 生成 balanceMask[4]，写入配置寄存器 A/B 的 DCC 位（write_cfg）
       c. 相邻通道能否同时打开待定，确认前不要实现奇偶交替
       d. isActive = true
  输出: 无

方法 BalanceService.setManualMask(mask):
  功能: 手动设置均衡掩码 (CAN 命令触发)
  输入: mask — 4 颗 AFE 的 DCC 掩码
  流程:
    1. mode = MANUAL
    2. 遍历 dev_gt2818s_01..04，write_cfg 写入对应 DCC
  输出: 成功/失败

方法 BalanceService.stop():
  功能: 停止所有均衡
  流程: 遍历四颗 AFE，清除 DCC 后 write_cfg
  输出: 无
```

#### 6.5.2 对象方法

```
方法 FaultDetectService.init():
  功能: 初始化故障检测服务，加载阈值配置
  输出: 无

方法 FaultDetectService.evalAll():
  功能: 全量故障评估 (100ms 周期调用)
  流程:
    1. 电压故障评估:
       遍历 cellData[0..63]:
         若 voltage > ovThreshold → 置位 FAULT_OV
         若 voltage < uvThreshold → 置位 FAULT_UV
       去抖处理: 连续 20 次 (2s) 检测到才确认

    2. 温度故障评估:
       遍历 tempData[0..15]:
         若 temp > otThreshold → 置位 FAULT_OT
         若 temp < utThreshold → 置位 FAULT_UT

    3. 断线检测:
       遍历 Afe[0..3]:
         若均衡开启后电压 < openWireThreshold → 置位 FAULT_OPEN_WIRE

    4. AFE 通信故障:
       检查 Afe[0..3].commErrCount:
         若 commErrCount > afeCommMaxRetry → 置位 FAULT_AFE_COMM

    5. 更新 activeFaults 和 latchedFaults
  输出: 无 (结果存入属性中)

方法 FaultDetectService.clearFault(faultMask):
  功能: 清除指定锁存故障
  输入: faultMask — 需清除的故障位
  输出: 无

方法 FaultDetectService.getActiveFaults():
  功能: 获取当前活跃故障位图
  输出: 32-bit 故障标志
```

### 8.9 参数管理服务

> **设计标识：** BSW_PMGT_001  
> **追溯需求：** REQ-BAL-001(均衡阈值), REQ-FLT-001~004(故障阈值), REQ-CAN-002~003(CAN参数配置), REQ-REL-004(配置持久化)  
> **依赖 BSP 对象：** Eeprom, CanPhy  
> **核心概念：** 四张参数表 + CAN 读写接口

#### 8.9.1 设计概述

参数管理服务（ParamManager）是本系统的**配置中心**，负责管理所有可配置参数的生命周期。它维护四张参数表，并对外提供统一的读写接口。

```
                              CAN 命令 (主控)
                                   │
                             ┌─────▼──────┐
                             │   CAN CMD  │
                             │  Processor │
                             └─────┬──────┘
                                   │ 通过参数 ID 读写
                                   ▼
┌──────────────────────────────────────────────────────────────────┐
│                      ParamManager                                │
│                                                                  │
│  ┌──────────────────────┐       ┌──────────────────────────┐     │
│  │  defaultParamTable[] │◄──────│     eepParamTable[]      │     │
│  │  (const, 存放于FLASH) │       │  (EEPROM 持久化副本)      │     │
│  │  不可修改             │       │  上电→加载到dynamic      │     │
│  └──────────────────────┘       │  CAN→写入更新+校验        │     │
│         │                       └──────────────────────────┘     │
│         │ 初始值来源                       │                     │
│         ▼                                │                     │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │               dynamicParamTable[] (RAM)                  │    │
│  │  工作参数缓存 —— 各 BSW 服务对象从这里读取配置值          │    │
│  │  CAN 可通过参数 ID 直接修改此表                          │    │
│  └─────────────────────────────────────────────────────────┘    │
│         │                                                       │
│         ├── 被 AnalogSampleService 读取 (OV/UV阈值)              │
│         ├── 被 BalanceService 读取 (均衡阈值)                    │
│         └── 被 FaultDetectService 读取 (故障阈值)                │
└──────────────────────────────────────────────────────────────────┘
```

**参数生命周期：**

```
首次上电或 EEPROM 校验失败:
  defaultParamTable → copy → dynamicParamTable
  defaultParamTable → write → EEPROM eepParamTable

正常上电 (EEPROM 有效):
  EEPROM eepParamTable → read → dynamicParamTable

运行时 CAN 修改参数:
  CAN → 参数ID + 新值 → ParamManager.update(id, value)
    ├── 校验范围（min/max）
    ├── 更新 dynamicParamTable
    └── 可选择同步写入 EEPROM (通过 CAN 命令控制)

运行时 CAN 读取参数:
  CAN → 参数ID → ParamManager.read(id) → 返回当前值
```

#### 8.9.2 参数定义

每个参数的元数据由以下字段描述：

```
参数元数据 (每一条):
  - id              : 参数唯一标识 (uint16_t, 用于 CAN 协议索引)
  - name            : 参数名称 (调试用)
  - defaultValue    : 默认值
  - minValue        : 最小值 (修改时校验)
  - maxValue        : 最大值 (修改时校验)
  - unit            : 单位 (℃/mV/A/...)
  - access          : 访问权限 (R/ W/ RW)
  - stored          : 是否存入 EEPROM
```

#### 8.9.4 对象属性

```
对象 ParamManager:
  属性:
    # 四张参数表
    - defaultTable[]     : const 默认参数表 (存放于 Flash, 编译时确定)
    - eepTable[]         : EEPROM 参数表缓存 (用于 EEPROM 读写)
    - dynamicTable[]     : 运行时工作参数表 (各服务通过接口读取此表)
    - eepromSyncPending  : EEPROM 写入挂起标志 (防频繁写入)

    # EEPROM 相关
    - eepromMagic        : EEPROM 有效标志 (校验用)
    - eepCrcValid        : EEPROM CRC 校验结果

    # CAN 参数访问接口 (注册到 CanCommService)
    - paramReadHandler   : 参数读取回调 (通过 CAN 调用)
    - paramWriteHandler  : 参数写入回调 (通过 CAN 调用)
```

#### 8.9.5 对象方法

```
方法 ParamManager.init():
  功能: 初始化参数管理服务
  流程:
    1. 将 defaultTable[] 加载到 dynamicTable[]
    2. 尝试从 EEPROM 读取 eepParamTable:
       a. 检查魔数
       b. CRC16 校验
       c. 校验通过 → 将 eepParamTable 覆盖加载到 dynamicTable[]
       d. 校验失败 → 保持默认值, 并将 defaultTable[] 写入 EEPROM
    3. 将参数读写句柄注册到 CanCommService:
       - 注册 forEachParam 回调, 使 CAN 可读取参数列表
       - 注册 onParamWrite 回调, 使 CAN 可修改参数
  输出: 无

方法 ParamManager.read(paraId):
  功能: 读取指定参数的当前值
  输入: paraId — 参数 ID
  流程:
    1. 在 dynamicTable[] 中查找 paraId
    2. 返回对应值
  输出: 参数值 (uint32_t), 以及参数元数据
  说明: 各 BSW 服务通过此接口获取配置值

方法 ParamManager.write(paraId, value, saveToEep):
  功能: 写入指定参数的值
  输入: paraId — 参数 ID, value — 新值, saveToEep — 是否同步写 EEPROM
  流程:
    1. 校验 paraId 是否有效
    2. 校验 value 是否在 [minValue, maxValue] 范围内
    3. 更新 dynamicTable[paraId] = value
    4. IF saveToEep == TRUE:
       a. 更新 eepTable[] 对应项
       b. 调用 Eeprom.writeConfig 写入 EEPROM
       c. 设置 eepromSyncPending = FALSE
    5. ELSE:
       a. 设置 eepromSyncPending = TRUE
  输出: 成功/失败 (含失败原因: ID无效/值越界/EEPROM写入失败)

方法 ParamManager.saveAllToEep():
  功能: 将所有 dynamicTable 中标记为 "存E2" 的参数批量写入 EEPROM
  流程:
    1. 遍历 dynamicTable[]
    2. 对每个存E2标志的参数, 更新 eepTable[]
    3. 计算 CRC16
    4. 调用 Eeprom.writeConfig(eepTable, len)
  输出: 成功/失败

方法 ParamManager.loadFromEep():
  功能: 从 EEPROM 加载参数
  流程:
    1. 调用 Eeprom.readConfig(eepTable)
    2. CRC16 校验
    3. 校验通过 → 复制 eepTable → dynamicTable
    4. 校验失败 → 保持当前 dynamicTable 不变
  输出: 成功/失败 (含校验状态)

方法 ParamManager.resetToDefaults():
  功能: 将所有参数恢复为出厂默认值
  流程:
    1. 复制 defaultTable[] → dynamicTable[]
    2. 复制 defaultTable[] → eepTable[]
    3. 写 EEPROM
  输出: 成功/失败

--- CAN 命令处理接口 (由 CanCommService 回调调用) ---

方法 ParamManager.handleCanRead(paraId):
  功能: CAN 读参数命令处理
  流程:
    1. 根据 paraId 查找参数
    2. 读取 dynamicTable 中的当前值
    3. 构造 CAN 响应报文: [paraId | value | 元数据]
    4. 通过 CanPhy.send() 发送
  输出: 无

方法 ParamManager.handleCanWrite(paraId, value, saveToEep):
  功能: CAN 写参数命令处理
  流程:
    1. 调用 write(paraId, value, saveToEep)
    2. 构造 CAN 响应报文: [成功/失败码]
    3. 通过 CanPhy.send() 发送
  输出: 无

方法 ParamManager.handleCanList(startId, count):
  功能: CAN 批量读取参数列表 (用于主控初始化时同步参数)
  流程:
    1. 从 startId 开始, 读取 count 个参数的 ID+值+元数据
    2. 分多帧 CAN 报文发送
  输出: 无
```

#### 8.9.6 EEPROM 参数块格式

```
EEPROM 参数存储区 (从地址 0x0000 开始):

┌──────────────┬──────────┬──────────────────────────────────────┐
│ 地址偏移      │ 大小     │ 内容                                │
├──────────────┼──────────┼──────────────────────────────────────┤
│ 0x0000       │ 4 bytes  │ 魔数 MAGIC = 0xBMS_PARA             │
│ 0x0004       │ 2 bytes  │ 参数表版本号 (用于兼容性检查)         │
│ 0x0006       │ 2 bytes  │ 参数条目数量 N                       │
│ 0x0008       │ N×4 bytes│ 参数值数组 [val0, val1, ..., valN-1] │
│ 0x0008+N×4   │ 2 bytes  │ CRC16 校验 (整个块, 不含自身)        │
└──────────────┴──────────┴──────────────────────────────────────┘

参数值数组按参数 ID 顺序排列, 每个值固定 4 字节 (uint32_t).
总大小 = 8 + N×4 + 2 字节. N=14 时 = 8+56+2 = 66 字节.
```

#### 8.9.7 防频繁写入策略

为了防止 CAN 连续修改参数导致 EEPROM 寿命耗尽:

```
写入策略:
  - 单次写入: CAN 指定 saveToEep=TRUE → 立即写 EEPROM
  - 批量修改: CAN 多次写 (saveToEep=FALSE) →
    eepromSyncPending = TRUE
  - 延迟保存: 每 60s 检查 eepromSyncPending
    若为 TRUE → 调用 saveAllToEep()
  - 写保护: 写 EEPROM 前计算总写入次数计数,
    超过阈值 (如 100 万次/扇区) 发出警告
```

### 9.1 机制说明

策略层未设计。本节不是策略层。

早期目标是 BSP 不直接调用 MCAL，而是在初始化时把 MCAL 方法注册到钩子。当前代码没有采用这张表：`Dev_Gt2818s_t` 直接保存 `Periph_Spi_t *` 和 `Periph_Gpio_t *`，`dev_can0` 用 `register_rx_callback` 接收。下面的注册流程和钩子总表仅作历史目标，实施时以 §6、§7 的代码对象为准。

1. MCAL 层定义标准化的函数指针类型
2. 系统初始化阶段，MCAL 对象将自己的方法地址注册到 BSP 对象的钩子中
3. BSP 对象通过钩子函数指针调用 MCAL 层的功能

### 9.2 注册流程

```
初始化阶段:

  1. MCAL 层初始化:
     Spi1.init(1000)       → Spi1.transfer 指针有效
     GpioPort[E].initPin() → GpioPort[E].writePin 指针有效

  2. BSP 层注册钩子:
     Afe[0].hookSpiXfer = Spi1.transfer
     Afe[0].hookCsSet   = GpioPort[E].writePin

  3. BSP 层可正常调用:
     Afe[0].hookCsSet(csPin, LOW)
     Afe[0].hookSpiXfer(cmd, resp, len)
```

### 9.3 钩子接口总表

| BSP 对象 | 钩子名称 | 类型描述 | 连接目标 |
|---------|---------|---------|---------|
| Afe[id] | hookSpiXfer | 全双工 SPI 传输函数 | Spi1.transfer |
| Afe[id] | hookCsSet | GPIO 引脚输出函数 | GpioPort[E].writePin |
| Eeprom | hookI2cWrite | I2C 主机写函数 | I2cSw.masterWrite |
| Eeprom | hookI2cRead | I2C 主机读函数 | I2cSw.masterRead |
| Cd4051Mux | hookGpioSet | GPIO 引脚输出函数 | GpioPort[E].writePin |
| CanPhy | hookCanInit | CAN 初始化函数 | Can0.init |
| CanPhy | hookCanSend | CAN 发送函数 | Can0.send |
| CanPhy | hookCanRecv | CAN 接收函数 | Can0.receive |
| CanPhy | hookCanStatus | CAN 状态查询函数 | Can0.getBusStatus |
| AddrHandler | hookGpioRead | GPIO 引脚输入函数 | GpioPort[E].readPin |
| AddrHandler | hookGpioSet | GPIO 引脚输出函数 | GpioPort[E].writePin |

### 9.4 层间调用数据流示例：电压采集

以下展示一次电压采集任务的完整层间调用链：

```
[BSW] AnalogSampleService.voltSample()
  │
  ├── step=0: 调用 Afe[0].adcv()
  │       │
  │       ├── Afe[0].hookCsSet(CS0, LOW)    ← 通过钩子
  │       │      └── GpioPort[E].writePin(PE0, 0)
  │       │              └── 写 MCU GPIO 寄存器       [MCAL 层]
  │       │
  │       ├── Afe[0].hookSpiXfer(cmd, resp, 2) ← 通过钩子
  │       │      └── Spi1.transfer(cmd, resp, 2)
  │       │              └── 写/读 SPI 寄存器         [MCAL 层]
  │       │
  │       └── Afe[0].hookCsSet(CS0, HIGH)
  │
  └── step=1: 调用 Afe[0].rdcv()
          │
          └── (同上，通过钩子调用 MCAL 层 SPI 和 GPIO)
```

## 10. 主程序框架与调度设计

### 10.1 调度模型

目标设计，无 `main`。伪代码里的 PA0、PE0、SPI1、1 MHz 和钩子赋值是旧草案，引脚以附录 C 为准，AFE 调用以 `dev_gt2818s_xx.func` 为准。看门狗和 SysTick 对象尚未编码。

采用**前后台系统**（Super Loop + SysTick 中断），按固定周期轮询执行各 BSW 服务。

```
┌────────────────────────────────────────────────────────────────┐
│  ISR 层 (中断服务)                                               │
│                                                                  │
│  TimerSys.irqHandler()   ← SysTick 1ms 中断，驱动时间标志         │
│  Can0.irqHandler()       ← CAN 接收中断，存入 RX 队列             │
└──────────────────────────────────────────────────────────────────┘
                            │
                            ▼ 设置时间标志
┌──────────────────────────────────────────────────────────────────┐
│  Super Loop (主循环)                                             │
│                                                                  │
│  LOOP:                                                            │
│    Wdt.feed()                                                    │
│                                                                  │
│    IF (flag_10ms)  →  AnalogSampleService.voltSample()           │
│                                                                  │
│    IF (flag_100ms) →  AnalogSampleService.tempSample()           │
│                       BalanceService.process()                   │
│                       FaultDetectService.evalAll()               │
│                                                                  │
│    IF (flag_1s)    →  CanCommService.sendHeartbeat()             │
│                       CanCommService.sendVoltage()               │
│                       CanCommService.sendTemperature()           │
│                       CanCommService.sendBalanceStatus()         │
│                       SelfTestService.runtimeCheck()             │
│                       ParamManager.saveAllToEep()  ← 延迟写E2   │
│                                                                  │
│    CanCommService.processTxQueue()                                │
│    ← 处理 CAN RX 队列                                             │
│  END LOOP                                                         │
└──────────────────────────────────────────────────────────────────┘
```

### 10.2 任务周期与优先级

| 任务 | 周期 | 对应 BSW 方法 | 优先级 |
|------|------|-------------|--------|
| SysTick 刷新 | 1ms | TimerSys.irqHandler | 最高 (中断) |
| CAN 接收 | 异步 | Can0.irqHandler / CanCommService.processRxMsg | 高 (中断) |
| 电压采集轮询 | 10ms | AnalogSampleService.voltSample | 中 |
| 温度采集 | 100ms | AnalogSampleService.tempSample | 中 |
| 均衡管理 | 100ms | BalanceService.process | 中 |
| 故障诊断 | 100ms | FaultDetectService.evalAll | 中 |
| CAN 上报 | 1s | CanCommService.sendXXX | 低 |
| 参数管理 (延迟写E2) | 1s | ParamManager.saveAllToEep | 低 |
| 运行时自检 | 1s | SelfTestService.runtimeCheck | 低 |

### 10.3 主程序伪代码

```
FUNC main()
    // === 第一阶段: MCAL 层初始化 ===
    TimerSys.init()               // SysTick 1ms
    Spi1.init(1000)               // SPI 1MHz
    I2cSw.init(GPIOB, GPIO_PIN_6, GPIOB, GPIO_PIN_7, SPEED_STANDARD) // 软件 I2C
    Can0.init(500000)             // CAN 500kbps
    GpioPort[A].initPin(PA0, OUTPUT_PP)
    GpioPort[A].initPin(PA1, OUTPUT_PP)
    GpioPort[E].initPin(PE0..PE9, ...)
    Uart2.init(115200)
    NvicMgr.enableIrq(CAN_IRQ, 1)
    NvicMgr.enableIrq(SYSTICK_IRQ, 0)

    // === 第二阶段: 钩子注册 + BSP 层初始化 ===
    // AFE 注册钩子并初始化
    FOR id = 0 TO 3
        Afe[id].hookSpiXfer = CALLBACK(Spi1.transfer)
        Afe[id].hookCsSet   = CALLBACK(GpioPort[E].writePin)
        Afe[id].init()
    END FOR

    // 其他 BSP 对象注册钩子并初始化
    Eeprom.hookI2cWrite = CALLBACK(I2cSw.masterWrite)
    Eeprom.hookI2cRead  = CALLBACK(I2cSw.masterRead)
    Eeprom.init()

    Cd4051Mux.hookGpioSet = CALLBACK(GpioPort[E].writePin)

    CanPhy.hookCanInit   = CALLBACK(Can0.init)
    CanPhy.hookCanSend   = CALLBACK(Can0.send)
    CanPhy.hookCanRecv   = CALLBACK(Can0.receive)
    CanPhy.hookCanStatus = CALLBACK(Can0.getBusStatus)
    CanPhy.init()

    AddrHandler.hookGpioRead = CALLBACK(GpioPort[E].readPin)
    AddrHandler.hookGpioSet  = CALLBACK(GpioPort[E].writePin)

    // === 第三阶段: BSW 层初始化 ===
    AddressService.assign()
    ParamManager.init()                     // 参数管理 (从EEPROM加载或默认)
    CanCommService.init(AddressService.getNodeId())
    AnalogSampleService.init()
    BalanceService.init()
    FaultDetectService.init()
    SelfTestService.powerOnTest()

    // === 第四阶段: 看门狗启用 ===
    Wdt.init(3000)

    // === 主循环 ===
    LOOP
        Wdt.feed()

        // LED 运行指示 (500ms 翻转)
        IF (TimerSys.getTick() % 500 == 0) DO
            GpioPort[A].togglePin(PA0)
        END IF

        IF (flag_10ms) DO
            flag_10ms = FALSE
            AnalogSampleService.voltSample()
        END IF

        IF (flag_100ms) DO
            flag_100ms = FALSE
            AnalogSampleService.tempSample()
            BalanceService.process()
            FaultDetectService.evalAll()

            // 故障时点亮错误 LED
            IF (FaultDetectService.getActiveFaults() != 0) DO
                GpioPort[A].writePin(PA1, HIGH)
            ELSE
                GpioPort[A].writePin(PA1, LOW)
            END IF
        END IF

        IF (flag_1s) DO
            flag_1s = FALSE
            CanCommService.sendHeartbeat()
            CanCommService.sendVoltage()
            CanCommService.sendTemperature()
            CanCommService.sendBalanceStatus()
            SelfTestService.runtimeCheck()
            ParamManager.saveAllToEep()       // 延迟写入 EEPROM
        END IF

        // 异步处理 CAN 收发
        CanCommService.processTxQueue()

        WHILE (CanPhy.receive(msg) == SUCCESS) DO
            CanCommService.processRxMsg(msg)
        END WHILE
    END LOOP
END FUNC
```

## 11. 系统状态机设计

### 11.1 系统主状态机

```
状态: SYS_INIT
    进入条件: 上电复位
    动作: MCAL 初始化 → BSP 钩子注册 → BSW 初始化
    退出条件: 所有初始化完成 → SYS_SELF_TEST

状态: SYS_SELF_TEST
    动作: SelfTestService.powerOnTest()
          AFE 自检、EEPROM 通信检测、CAN 状态检测
    退出条件: 全部通过 → SYS_NORMAL
              关键项失败 → SYS_FAULT

状态: SYS_NORMAL
    动作: 循环执行:
          - AnalogSampleService (10ms/100ms)
          - BalanceService (100ms)
          - FaultDetectService (100ms)
          - CanCommService (1s + 异步)
    故障触发: FaultDetectService 检测到故障 → SYS_FAULT
    CAN 休眠指令: → SYS_SLEEP

状态: SYS_FAULT
    动作: 置位故障标志、CAN 上报故障、执行保护动作
          (停止均衡、标记无效通道等)
    退出条件: 故障清除指令 → SYS_NORMAL
              关键故障自动恢复 → SYS_NORMAL

状态: SYS_SLEEP
    动作: AFE 进入 SLEEP 模式、停止采集、等待唤醒
    退出条件: CAN 唤醒指令 → SYS_NORMAL
```

### 11.2 AFE 采集状态机 (每颗 AFE 独立)

目标设计。四颗对象是 `dev_gt2818s_01`～`_04`，启动转换和读回对应 `func.adcv`、`func.rdcv`。每颗 18 路。

```
状态: AFE_IDLE
    动作: 等待采集指令
    退出条件: voltSample() 发起 adcv() → AFE_CONVERTING

状态: AFE_CONVERTING
    动作: 等待 AFE 内部 ADC 转换完成
    超时处理: 若超时则通信错误计数+1 → AFE_IDLE
    退出条件: 转换完成 → AFE_READBACK

状态: AFE_READBACK
    动作: 发送 RDCV 命令读取电压数据、PEC 校验
    退出条件: PEC 通过 → 数据存入缓存 → AFE_IDLE
              PEC 失败 → 重试 (最多 3 次)
                          3 次都失败 → 通信故障 → AFE_IDLE
```

## 13. 错误处理与异常恢复设计

### 13.1 错误等级

| 等级 | 说明 | 处理方式 |
|------|------|---------|
| 致命 | 系统无法正常运行 | 硬件看门狗复位 |
| 严重 | 局部功能丧失 | 进入 FAULT 状态，CAN 上报 |
| 警告 | 异常但不影响核心功能 | 记录日志，继续运行 |
| 信息 | 状态变化 | 仅记录 |

### 13.2 异常场景恢复策略

| 异常场景 | 检测方式 | 恢复策略 |
|---------|---------|---------|
| AFE SPI 通信失败 | PEC 校验错误累加 | 重试 3 次，失败则标记故障，尝试复位 AFE |
| AFE 自检失败 | selfTest() 返回错误 | 标记该 AFE 不可用，上报，跳过其采集 |
| CAN 总线关闭 | Can0.getBusStatus | 等待协议自动恢复时间 |
| EEPROM I2C 无应答 | I2cSw.checkDevice | 使用默认配置，周期性重试 |
| 均衡温度超限 | BalanceService 内部检查 | 自动关闭均衡通道 |
| 看门狗复位 | 复位后读取 RCC 标志 | 记录复位事件到 EEPROM |

### 13.3 看门狗保护策略

```
喂狗点:
  - 主循环每个周期开头: Wdt.feed()
  - 关键任务 (AFE 采集) 执行前: Wdt.feed()

超时设定: 3000ms

预期行为:
  - 若主循环卡死超过 3s → 硬件复位
  - 复位后通过读取复位原因标志区分:
    上电复位 / 看门狗复位 / 外部复位
```

### 附录 D：代码与设计偏差

这些是当前实现里的缺陷，不是设计目标。

| 位置 | 现象 |
|------|------|
| `periph_spi.c` 的 `spi_init` | 访问 `self->pins`，结构体字段是 `physical_pins` |
| `dev_gt2818s.c` 的 `adcv` | `adcv_config` 未初始化就按位或 |
| `periph_can.c` 的发送 | `tx_msg.ff = CAN_FF_EXTENDED`，同时只填写 `stdid` |
| `periph_can.c` 的波特率 | 注释按 72 MHz 计算 500 kbps；`system_gd32f30x.c` 选择的是 48 MHz |
| `periph_can.c` 的 `can_init` | 调用 `can_init(can_periph, ...)`，形参名与未限定的 `can_periph` 易混淆，应按 `self->can_periph` 使用 |
