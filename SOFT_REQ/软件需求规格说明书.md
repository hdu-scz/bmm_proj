## 1. 引言

### 1.1 编写目的

本文档旨在明确 BMS 从控模块的软件需求，为后续的软件设计、编码实现、单元测试和系统集成提供依据。本文档面向软件开发工程师、测试工程师及项目管理人员。

### 1.2 适用范围

本需求规格说明书适用于基于 GD32F30x MCU、4 片 GT2818S AFE 芯片的 BMS 从控模块软件开发项目。

## 2. 总体描述

### 2.1 产品概述

本产品为 **BMS 从控模块**，部署于储能/动力电池系统中，负责对磷酸铁锂模组进行电压和温度的实时采集、被动均衡控制以及故障保护。采样前端为 4 片 GT2818S。底层按芯片最大能力设计：每片 18 路电压，共 72 路；温度使用各片 GPIO 的 ADC。应用层配置实际启用的电芯和温度通道，不把 64 串或 16 路写成固定硬件。每个从控模块通过 CAN 总线与主控（BCU/BMU）进行通信，支持多从控级联（8 个以上从控模块）。

## 3. 系统架构

### 3.1 物理架构

从控模块由以下硬件单元组成：

| 单元 | 描述 |
|------|------|
| **MCU 单元** | GD32F30x，负责逻辑控制与通信 |
| **AFE 采集单元** | 4× GT2818S，每颗 18 路电压通道，底层全部采集。应用层配置哪些通道是有效电芯 |
| **温度采集单元** | CD4051 模拟开关切换 NTC，再送入 GT2818S 采样。应用层配置实际启用的温度通道 |
| **均衡单元** | GT2818S 配置寄存器 A/B 中的 DCC0～DCC18 放电开关 |
| **CAN 通信单元** | GD32 内置 CAN 控制器 + CAN 收发器 |
| **存储单元** | I2C 接口 EEPROM（E2PROM），存储参数配置表、NTC 校准表及故障记录 |
| **地址单元** | GPIO 级联握手电路（one by one 级联方式） |

### 3.2 与外部系统的交互

```
┌──────────┐    CAN Bus     ┌──────────────┐    SPI      ┌──────────────────┐
│  BMS     │◄──────────────►│  GD32F30x    │◄───────────►│  GT2818S ×4      │
│  Master  │  自定义协议    │  (Slave)     │   4×CS      │  ┌──────┐       │
└──────────┘  500kbps       │  ┌───────┐   │             │  │ GPIO │◄─NTC  │
                            │  │ I2C   │◄──┤             │  └──────┘ 16路  │
                            │  │→ E2  │   │             └──────────────────┘
                            │  └───────┘   │
                            └──────────────┘
```

## 4. 软件分层架构

### 4.1 分层设计原则

软件采用**分层架构**，自下而上分为五层。上层只调用相邻的下一层，每层职责明确，便于替换和测试。

```
┌──────────────────────────────────────────┐
│  ASW   应用软件层                         │
├──────────────────────────────────────────┤
│  BSW   基础软件层                         │
├──────────────────────────────────────────┤
│  BSP   板级支持包                         │
├──────────────────────────────────────────┤
│  MCAL  面向对象化封装 MCU 外设             │
├──────────────────────────────────────────┤
│  HAL   厂商外设库，直接操作寄存器          │
└──────────────────────────────────────────┘
```

### 4.2 各层职责

| 层级 | 职责 |
|------|------|
| **HAL** | 厂商外设库，直接操作 MCU 寄存器 |
| **MCAL** | 以结构体和函数指针把 MCU 外设封装成对象 |
| **BSP** | 板级支持包，封装板上的芯片和电路 |
| **BSW** | 基础软件层，提供与具体项目无关的通用服务 |
| **ASW** | 应用软件层，按项目配置组织采集、均衡、故障和通信流程 |

## 5. 功能需求

### 5.1 电压采集功能

#### 5.1.1 前端电压采集功能

| 编号 | REQ-VOLT-001 |
|------|-------------|
| **名称** | 前端电压采集 |
| **描述** | 系统应通过 4 片 GT2818S 采集单体电压。每片 `adcv` 启动转换，`rdcv` 读回 RDCVA～RDCVF 共 6 组、每组 3 节，合计 18 路；四片合计 72 路。底层保留全部通道的原始结果 |
| **输入** | AFE 电压寄存器原始值 |
| **处理** | ① 发送 `adcv` → ② 等待转换完成 → ③ `rdcv` 读取电压寄存器 → ④ 进行 PEC15 校验（多项式 0x4599） → ⑤ 将通过校验的原始值转换为 mV |
| **输出** | 各采样通道的原始电压（单位：mV） |
| **采样周期** | 全部电压通道扫描周期 < 100ms |
| **异常处理** | PEC 校验失败则丢弃该帧，并累加通信错误计数 |

#### 5.1.2 电压数据处理功能

前端采集结果进入数据处理。处理顺序为：数据有效性判断、数据置信、滤波、主动均衡电压补偿。只有完成处理的电压供总电压和主动均衡使用。

| 编号 | REQ-VOLT-002 |
|------|-------------|
| **名称** | 数据有效性判断 |
| **描述** | 系统应判断每个采样通道的电压是否有效 |
| **判断** | ① 通道已在应用配置中启用 ② 本帧 PEC 校验通过 ③ 电压落在配置的有效范围内 |
| **输出** | 每个通道的有效标志。未启用、校验失败或超出范围的数据标记为无效，不进入后续处理 |

| 编号 | REQ-VOLT-003 |
|------|-------------|
| **名称** | 数据置信 |
| **描述** | 系统应对连续有效的采样建立置信，避免单次跳动被当作真实电压 |
| **处理** | 同一通道连续有效次数达到配置值后，该电压标记为可信。中间出现无效采样则重新计数 |
| **输出** | 每个通道的可信标志和可信电压。未达到置信次数的通道保持上一次可信电压 |

| 编号 | REQ-VOLT-004 |
|------|-------------|
| **名称** | 滤波处理 |
| **描述** | 系统应对可信电压进行滤波，抑制采样噪声 |
| **处理** | 对已置信的通道电压按配置的滤波参数滤波。无效或尚未置信的采样不更新滤波结果 |
| **输出** | 各通道滤波后电压 |

| 编号 | REQ-VOLT-005 |
|------|-------------|
| **名称** | 主动均衡电压补偿 |
| **描述** | 主动均衡改变了被测电芯的采样电压。系统应按均衡状态对滤波后电压进行补偿，得到用于判断的电芯电压 |
| **输入** | 滤波后电压；该通道的主动均衡开关状态；补偿参数 |
| **处理** | 通道正在主动均衡时，按补偿参数修正电压。通道未均衡时不做补偿 |
| **输出** | 补偿后的电芯电压 |

| 编号 | REQ-VOLT-006 |
|------|-------------|
| **名称** | 总电压计算 |
| **描述** | 系统应对配置为有效、且已得到补偿后电压的电芯求和，得到模组总电压 |
| **处理** | 未启用通道不计入 |
| **输出** | 总电压值（单位：V，精度 0.1V） |

### 5.2 温度采集功能

#### 5.2.1 温度采集

| 编号 | REQ-TEMP-001 |
|------|-------------|
| **名称** | 温度采集 |
| **描述** | NTC 经 CD4051 选通后，由 GT2818S 的 GPIO ADC 采样。应用层配置实际启用的温度通道 |
| **原理** | ① MCU 通过 GPIO 设置 CD4051 通道地址并等待开关稳定 → ② 对接入公共端的 GT2818S GPIO 发送 `adgp` 启动转换 → ③ 转换完成后 `rdgp` 读回 → ④ 进行 PEC15 校验 → ⑤ 将通过校验的采样值按 NTC 换算为温度 |
| **输出** | 各启用通道的原始温度（单位：℃） |
| **采样周期** | 已启用温度通道的全扫描周期 < 1s |
| **异常处理** | PEC 校验失败则丢弃该帧，并累加通信错误计数 |

#### 5.2.2 温度数据处理

采集结果进入数据处理，包含滤波、数据有效性判断和开短路判断。

| 编号 | REQ-TEMP-002 |
|------|-------------|
| **名称** | 滤波 |
| **描述** | 系统应对温度采样进行滤波，抑制开关切换和采样噪声 |
| **处理** | 按配置的滤波参数处理各启用通道的温度。校验失败的采样不更新滤波结果 |
| **输出** | 各通道滤波后温度 |

| 编号 | REQ-TEMP-003 |
|------|-------------|
| **名称** | 数据有效性判断 |
| **描述** | 系统应判断每个温度通道的数据是否有效 |
| **判断** | ① 通道已在应用配置中启用 ② 本帧 PEC 校验通过 ③ 滤波后温度落在配置的有效范围内 |
| **输出** | 每个通道的有效标志。未启用、校验失败或超出范围的数据标记为无效 |

| 编号 | REQ-TEMP-004 |
|------|-------------|
| **名称** | 开短路判断 |
| **描述** | 系统应判断 NTC 回路是开路还是短路 |
| **判断** | 采样值达到配置的开路阈值时判定开路；达到配置的短路阈值时判定短路 |
| **输出** | 各通道的开路或短路标志。被判定为开路或短路的通道不作为有效温度使用 |

| 编号 | REQ-TEMP-005 |
|------|-------------|
| **名称** | 最高/最低温度 |
| **描述** | 系统应从有效温度通道中得到最高温度、最低温度及其通道号 |
| **输出** | 最高温度及通道号、最低温度及通道号 |

### 5.3 主动均衡控制功能

| 编号 | REQ-BAL-001 |
|------|-------------|
| **名称** | 主动均衡控制 |
| **描述** | 系统通过 USART 接口控制主动均衡芯片组，对指定节数执行主动均衡的启动和停止 |
| **处理** | ① 均衡信息有效性检查：确认目标节数和启停指令完整、合法后才下发 → ② 系统状态检查：确认当前系统状态允许执行该启停操作 → ③ 异常处理：检查不通过或 USART 控制失败时，不执行本次启停，并记录异常 |

### 5.5 CAN 通信功能

| 编号 | REQ-CAN-001 |
|------|-------------|
| **名称** | CAN 通信配置 |
| **描述** | 系统应能初始化 CAN 控制器，配置为 500kbps 波特率，CAN 2.0B 标准 |
| **处理** | ① 配置 CAN 引脚（GPIO 复用）→ ② 设置波特率 → ③ 设置过滤器 → ④ 使能中断 |

| 编号 | REQ-CAN-002 |
|------|-------------|
| **名称** | 数据上报 |
| **描述** | 系统应能通过 CAN 总线周期性上报以下数据 |
| **内容** | ① 单体电压数据 ② 温度数据 ③ 故障状态 ④ 均衡状态 ⑤ 模块状态 |
| **周期** | 各报文周期可配置（默认 100ms ~ 1000ms） |

| 编号 | REQ-CAN-003 |
|------|-------------|
| **名称** | 命令接收 |
| **描述** | 系统应能接收来自主控的命令帧 |
| **命令类型** | ① 均衡控制指令 ② 参数配置指令（详见 §5.8） ③ 同步采集指令 ④ 复位指令 |

| 编号 | REQ-CAN-005 |
|------|-------------|
| **名称** | 参数远程读写 |
| **描述** | 系统应能通过 CAN 总线接收参数读写命令，支持按参数 ID 读取当前值、写入新值、批量列举参数列表 |
| **读参数** | 主控发送读参数命令（含参数 ID），从控返回参数当前值及元数据 |
| **写参数** | 主控发送写参数命令（含参数 ID + 新值），从控校验范围后更新，可选择是否持久化到 EEPROM |
| **列举参数** | 主控发送列举命令，从控返回所有可配置参数的 ID、名称、当前值、范围 |
| **恢复默认** | 主控发送恢复出厂命令，从控将所有参数重置为默认值并写入 EEPROM |

| 编号 | REQ-CAN-004 |
|------|-------------|
| **名称** | 心跳报文 |
| **描述** | 系统应按固定周期发送心跳报文，表明模块在线 |
| **周期** | 1s |

### 5.6 自动地址分配功能

| 编号 | REQ-ADDR-001 |
|------|-------------|
| **名称** | 从控节点地址分配 |
| **描述** | 系统应能通过硬件 IO 级联握手方式自动分配 CAN 节点 ID |
| **处理** | ① 上电后检测 IO 级联输入状态（首级接 GND/固定电平）→ ② 根据级联输入信号确定本机地址 → ③ 通过输出 IO 将地址/使能信号 one by one 传递给下一级从控 |
| **地址范围** | 1 ~ N（N 为从控总数） |
| **冲突检测** | 地址分配完成后发送地址声明报文，若检测到冲突则重新分配 |

### 5.8 参数管理功能

| 编号 | REQ-PARA-001 |
|------|-------------|
| **名称** | 参数配置表 |
| **描述** | 系统应维护一套完整可配置的参数集，包含阈值、定时、通信等全部可调参数 |
| **内容** | ① 电压阈值（过压/欠压） ② 温度阈值（过温/低温） ③ 均衡参数（开启压差/停止压差/超时/停止温度） ④ 故障参数（断线阈值/去抖时间） ⑤ 通信参数（心跳间隔/节点ID/波特率） ⑥ AFE 通信重试次数 |
| **默认值** | 系统内置编译时默认参数表，存放于 Flash |
| **可配置性** | 所有参数应支持通过 CAN 总线在线修改 |
| **持久化** | 修改后的参数应可持久化保存到 EEPROM，下次上电自动加载 |

| 编号 | REQ-PARA-002 |
|------|-------------|
| **名称** | 参数生命周期管理 |
| **描述** | 系统应管理参数的三态：默认值（const Flash）、工作值（RAM运行时）、持久化值（EEPROM） |
| **加载策略** | ① 上电优先从 EEPROM 加载 ② EEPROM 无效或首次上电时使用默认值 ③ 加载完成后写入 EEPROM 建立持久化副本 |
| **修改策略** | ① CAN 修改后立即更新 RAM 工作值 ② 可选择同步或延迟写入 EEPROM |
| **恢复出厂** | 应支持通过 CAN 命令一键恢复所有参数为出厂默认值 |

### 5.7 系统自检功能

| 编号 | REQ-DIAG-001 |
|------|-------------|
| **名称** | 上电自检（POST） |
| **描述** | 系统上电后应执行自检，确认各模块状态正常 |
| **检查项** | ① MCU 外设初始化检查 ② 四路 GT2818S 通信检查（读配置寄存器并做 PEC15 校验） ③ CAN 控制器检查。CVST/GPST/STATST 一类专用自检命令当前驱动未实现 |
| **结果** | 自检通过则进入正常运行状态，失败则上报故障 |

| 编号 | REQ-DIAG-002 |
|------|-------------|
| **名称** | 运行时自检 |
| **描述** | 系统在运行中应周期性执行自检 |
| **检查项** | ① AFE 通信状态 ② 均衡温度监控 ③ 看门狗喂狗 |
| **周期** | 1s |

## 6. 接口需求

### 6.1 AFE SPI 接口

以 `periph_spi0` 与四颗 `dev_gt2818s` 的片选为准。

| 项目 | 描述 |
|------|------|
| **外设** | SPI0，主机，软件 NSS |
| **时钟模式** | `SPI_CK_PL_HIGH_PH_2EDGE`（CPOL=1，CPHA=1，Mode 3） |
| **分频** | `SPI_PSC_8`。SCK 频率取决于 APB2 时钟，当前系统时钟宏为 48 MHz，实际 SCK 需与 GT2818S 手册核对，代码未再限制到 1 MHz |
| **数据格式** | MSB first，8-bit 帧。命令为 2 字节加 2 字节 PEC15 |
| **引脚** | PA5 = SCK，PA6 = MISO，PA7 = MOSI，四颗 AFE 共用 |
| **片选** | CS0 = PB12（`dev_gt2818s_01`），CS1 = PC4（`_02`），CS2 = PB1（`_03`），CS3 = PA2（`_04`），空闲为高 |

### 6.2 温度 GPIO 接口

NTC 接到 GT2818S 的 GPIO，由该芯片自己的 ADC 测量。MCU 不为温度提供模拟开关地址线。具体哪颗 AFE 的哪个 GPIO 对应哪路 NTC，由应用配置决定，本需求不写死引脚表。

### 6.2.1 已占用但功能未定义的 GPIO 与 ADC

`periph_io[]` 共 18 路，其中 4 路已用作 AFE 片选。其余 14 路已实例化、默认浮空输入，板级功能未定义：PC1、PA1、PA3、PA4、PB0、PB3、PA15、PA12、PA11、PA8、PC9、PC8、PC7、PC6。

MCU ADC 已有对象、用途未定义：ADC0 通道 10 = PC0（`periph_adc1`），ADC0 通道 12 = PC2（`periph_adc2`）。两路共用 ADC0。

### 6.3 CAN 接口

| 项目 | 描述 |
|------|------|
| **外设** | CAN0，引脚 PB8 = RX，PB9 = TX |
| **标准** | CAN 2.0B。代码目标波特率为 500 kbps，接收中断和全通滤波已写。分频注释按 72 MHz 计算（预分频 9，BS1=6TQ，BS2=3TQ），与当前 48 MHz 系统时钟宏不一致，实际波特率待核对 |
| **代码对象** | MCAL `periph_can0`，BSP `dev_can0` 经接收回调组装 `CanFrame_t` |
| **详细协议** | 帧 ID 与字节定义仍见独立文档《BMS 从控模块 CAN 通信协议规范.md》。该文件尚未入库 |

### 6.4 主从控交互时序需求

| 编号 | 需求 |
|------|------|
| REQ-SEQ-001 | 上电后从控应在 2s 内完成自检并发送首帧 CAN 报文（含地址和状态） |
| REQ-SEQ-002 | 从控地址分配失败时应进入“地址冲突”状态，并通过 CAN 上报错误 |
| REQ-SEQ-003 | 主控下发参数修改命令后，从控应在 100ms 内将新参数写入 EEPROM 并生效 |
| REQ-SEQ-004 | 总线离线超过 10s 后，从控应进入“离线保护”模式，停止均衡并保持最后有效状态 |
| REQ-SEQ-005 | 从控恢复在线后，应主动上报当前状态（电压、温度、故障）给主控 |
| **收发器** | 外部 CAN 收发器（如 TJA1050/SN65HVD230） |
| **终端电阻** | 120Ω（由硬件跳线决定） |

### 6.4 I2C 接口

| 项目 | 描述 |
|------|------|
| **接口类型** | 软件 I2C，对象 `periph_softi2c0`，PB6 = SCL，PB7 = SDA，默认标准速率（`delay_us = 5`） |
| **器件** | EEPROM（如 AT24Cxx 系列）。驱动对象尚未实现 |
| **用途** | 存储配置参数、校准表、故障记录等 |
| **容量要求** | ≥ 64KB（取决于配置表大小，具体待定） |

### 6.5 地址分配 IO 接口

| 项目 | 描述 |
|------|------|
| **方式** | One by one 级联握手（逐级传递） |
| **输入** | 1 路 GPIO（检测上级传递的地址/使能信号）。引脚尚未分配 |
| **输出** | 1 路 GPIO（将地址/使能信号传递给下一级从控）。引脚尚未分配 |
| **首级** | 第一个从控模块的输入接 GND 或上拉固定电平 |
| **协议** | 自定义 IO 级联手拉信号，逐级传递地址 |

**级联示意：**

```
 GND ──► Slave#1 IN ── OUT ──► Slave#2 IN ── OUT ──► ... ──► Slave#N
          (ID=1)                 (ID=2)                    (ID=N)
```

### 6.6 调试接口

| 项目 | 描述 |
|------|------|
| **调试方式** | IAR 仿真器（J-Link / GD-Link），SWD 接口 |
| **UART 打印** | 代码已有四路 115200 UART 对象：USART0（PA9 TX / PA10 RX）、USART1（PC10 TX / PC11 RX）、USART2（PB10 RX / PB11 TX）、USART3（PC12 TX / PD2 RX）。哪一路作为调试口未定义 |

## 9. 质量需求

### 9.1 可靠性

| 编号 | 需求 |
|------|------|
| REQ-REL-001 | 软件看门狗应确保死机时能在 3s 内自动复位 |
| REQ-REL-002 | SPI 通信异常时应自动重试，最多 3 次 |
| REQ-REL-003 | CAN 发送失败时应将报文存入发送缓冲区，等待下次发送机会 |
| REQ-REL-004 | 系统应具备参数持久化能力：运行时参数（阈值、配置等）应存入 EEPROM，上电加载，掉电不丢失 |
| REQ-REL-005 | EEPROM 中的参数块应包含魔数校验和 CRC16 校验，校验失败时自动回退到默认参数 |
| REQ-REL-006 | 系统应具备防频繁写入 EEPROM 的保护机制，避免因 CAN 频繁修改参数导致 EEPROM 寿命耗尽 |

### 9.2 可维护性

| 编号 | 需求 |
|------|------|
| REQ-MNT-001 | 代码应遵循分层架构设计，各层之间通过接口函数调用，不跨层访问 |

| REQ-MNT-003 | 配置参数应集中管理（bms_config.h），避免散落在各模块 |

### 9.3 可测试性

| 编号 | 需求 |
|------|------|
| REQ-TST-001 | 每个服务层模块应支持独立的单元测试 |
| REQ-TST-002 | 抽象层接口应支持 Mock 替换，便于 PC 端仿真测试 |
| REQ-TST-003 | 提供调试 UART 接口输出运行时关键信息 |

| REQ-TST-005 | 提供“诊断模式”开关，可通过 CAN 命令进入，输出内部状态用于调试 |

### 9.4 安全性（功能安全相关）

| 编号 | 需求 |

### 附录 A：GT2818S 命令与寄存器（与当前驱动一致）

命令为 16 bit，后跟 PEC15。写配置时数据为 6 字节加 2 字节 PEC。

| 命令 | 码 | 驱动方法 |
|------|----|----------|
| WRCFGA | 0x0001 | `write_cfg` |
| RDCFGA | 0x0002 | `read_cfg` |
| RDCVA | 0x0004 | `rdcv` |
| RDCVB | 0x0006 | `rdcv` |
| RDCVC | 0x0008 | `rdcv` |
| RDCVE | 0x0009 | `rdcv` |
| RDCVD | 0x000A | `rdcv` |
| RDCVF | 0x000B | `rdcv` |
| WRCFGB | 0x0024 | `write_cfg` |
| RDCFGB | 0x0026 | `read_cfg` |

配置寄存器 A 含 GPIO1～5 下拉、VUV/VOV、DCC1～12、DCT。配置寄存器 B 含 GPIO6～9 下拉、DCC13～18、DCC0、DTMEN、静默与诊断位。电压寄存器 6 组，每组 3 节，共 18 路。PEC 多项式为 0x4599。

`adcv`、`adgp` 的命令字由模式和通道拼出；`adcv` 当前实现使用了未初始化的配置变量，见详细设计中的代码偏差表。唤醒为两次 CS 低脉冲，每次约 150 μs。
